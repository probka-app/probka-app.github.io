# ai-text — виправлення безпеки 2026-11-26

**Проблема (аудит 01):** будь-який залогінений користувач міг викликати приховані промти (`sys`), «чистий» режим (`raw`) і зображення на дорожчих моделях за рахунок власника; обмеження — лише денна кількість запитів.

**Виправлення:** серверна політика `aiAccess` перед будь-яким читанням промтів чи викликом моделі.
- Роль власника — лише з `profiles.is_owner` на сервері; ролі, прапорці й демо-режим браузера ігноруються.
- Не-власник: `sys`, `raw`, злиття Біблій, зображення → `403 owner_only`.
- Не-власник без явного дозволу сервера (`settings.ai_public_enabled = 1`) → `403 ai_disabled`. Ключа в базі немає → платний AI для інших вимкнено за замовчуванням.
- Профіль недоступний → `503 policy_unavailable` (модель не викликається).

**Розгортання:** Supabase Edge Function `ai-text` v27 (2026-11-26), `verify_jwt=false` як і раніше (автентифікація в коді).
**Попередня версія:** v25/v26, той самий код, що в коміті `4573f99` (`supabase/functions/ai-text/index.ts`, sha256 `34a08bdf…7046`).
**Відкат:** розгорнути файл із коміту `4573f99` як `ai-text` з `verify_jwt=false`.
**Тести:** 12 офлайн-сценаріїв із заглушками Supabase/Anthropic (без мережі, без платних викликів): нова версія 12/12; стара 4/12 (підтверджує вразливість).
