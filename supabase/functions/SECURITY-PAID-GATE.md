# Шлюз платних операцій (Phase 02, 2026-11-26)

**Стан зараз:** у `public.settings` немає жодного ключа `paid_*`, тож усе платне вимкнено для всіх, **включно з власником**.

## Як працює
- Міграція `supabase/migrations/20261126_paid_gate.sql` (застосовано в проєкті 26.11) додає:
  - таблицю `paid_usage(day, svc, used)`, до якої мають доступ лише service_role;
  - функцію `paid_reserve(svc)`: **атомарно** резервує 1 одиницю (`INSERT … ON CONFLICT DO UPDATE … WHERE used < max`);
  - функцію `paid_check(svc)`: перевірка без резервування.
  `anon` і `authenticated` не можуть викликати жодну з них (перевірено наживо: `permission denied`).
- У кожній із 8 функцій (tts, stt, image-gen, stats-extract, kb-chat, video-spec, ai-text, voice-clone) **перехоплюється кожен вихідний запит**. Резерв потрібен для будь-якого хоста, крім бази Supabase і явно безкоштовних адрес:
  - YouTube oEmbed / Data API / обкладинки у video-spec;
  - Gemini Files API (лише завантаження файлу й опитування стану);
  - DELETE власного клону ElevenLabs.
  Тому новий провайдер, запасний шлях чи повтор не обходять шлюз.
- `paid_check` стоїть до списання безкоштовних квот користувача (у tts, stt, image-gen, stats-extract, kb-chat, video-spec — одразу після входу). Коли платне вимкнено, квоти не губляться.
- Черга воркера: `job_create` викликає `paid_reserve('worker_job')`. Нове платне завдання (ElevenLabs Scribe, Claude) не створюється без явного ввімкнення.
- Відповіді:
  - немає ключів або `enabled ≠ 1` → `403 paid_disabled`;
  - немає або некоректний ліміт → `403 paid_budget_missing`;
  - ліміт вичерпано → `429 paid_budget_exhausted`;
  - налаштування чи шлюз недоступні → `503 policy_unavailable`.
  Платного fallback немає.

## Ключі увімкнення (лише рішенням власника)
`paid_<svc>_enabled = 1` і `paid_<svc>_daily_max = N`. Значення `svc`: `tts`, `stt`, `image_gen`, `stats_extract`, `kb_chat`, `video_spec`, `ai_text`, `voice_clone`, `worker_job`.

**Важливо: `daily_max` — це кількість звернень до провайдера за добу UTC (для всіх користувачів разом), а не гроші.** Вартість одного звернення різна: залежить від моделі, довжини тексту чи аудіо, роздільності, кількості зображень. Ліміт не гарантує суми в доларах. Фактичні витрати контролюються лише на боці провайдера: ліміти й сповіщення в консолях Anthropic, Google, ElevenLabs, Cloudflare. Перед увімкненням треба оцінити ціну одного звернення й помножити на N.
- Одна дія користувача може використати кілька одиниць:
  - image-gen: до 3 генерацій і 2 перевірок;
  - video-spec: до 3 спроб і 1 запит на обкладинку;
  - ai-text: 1 повтор при порожній відповіді.
  Кожна спроба резервується окремо, тож ліміт N не перевищується.
- Для `worker_job` одиниця — це одне завдання. Скільки звернень до провайдера робить сам воркер, шлюз не обмежує: потрібен окремий ліміт у воркері (див. «Обмеження»).

## Перевірки
- **Офлайн**, `supabase/tests/atomic_gate_test.ts`: заглушки провайдерів, лічильник у справжній локальній PostgreSQL 16 з цією міграцією. Пройшло 81/81, справжніх платних викликів 0. Що покрито:
  - без входу;
  - власник без ключів, із квотами, що не списуються;
  - `enabled=0`;
  - немає ліміту;
  - шлюз недоступний;
  - кількість звернень дорівнює кількості резервів;
  - повтори й запасні провайдери після збою;
  - вичерпаний ліміт;
  - 25 одночасних запитів при ліміті 3 дають ≤3 звернення;
  - повторні запити після вичерпання;
  - видалення клону.
  Вивід: `supabase/tests/atomic_gate_results-2026-11-26.txt`.
- **SQL окремо:** 60 одночасних `paid_reserve` при ліміті 5 дали рівно 5 `ok` і 55 `paid_budget_exhausted`; без таблиці налаштувань — помилка, тобто відмова.
- **Наживо**, без платних викликів:
  - 8 функцій: `OPTIONS` → 200; без входу та з публічним ключем → `401 not_authenticated`; voice-clone → `503 no_key`, бо ключ ElevenLabs на сервері не задано;
  - прямий виклик `paid_reserve`, `paid_check`, `job_create` і читання `paid_usage` з публічним ключем → `permission denied`.
- **Звірка розгорнутого коду з репозиторієм:** 7 функцій ідентичні; ai-text перерозгорнуто (v30), бо у v29 було спотворено одне слово в прихованих промтах. Результат — у журналі Phase 02.
- **Шлях авторизованого власника наживо не перевірено:** потрібен його токен. На сайті будь-яка платна дія має повертати `403 paid_disabled`.

## Обмеження
- Воркер (Railway, репозиторій `yuvi-worker`) звертається до провайдерів без цього шлюзу. Нові завдання не створюються, але старі в черзі виконалися б. На 26.11 черга порожня.
- Ліміт рахує звернення, а не гроші (див. вище).

## Відкат (безпечний)
- **Не** на попередні вразливі версії функцій.
- Аварійний варіант: розгорнути `supabase/functions/_safe-stub/index.ts` під ім'ям потрібної функції (`verify_jwt=false`). Тоді все повертає 503, звернень до провайдерів немає.
- `supabase/migrations/20261126_paid_gate_ROLLBACK.sql` повертає `job_create` без шлюзу й прибирає таблицю та функції. Застосовувати **лише разом** із заглушками, бо інакше функції відмовлятимуть (503). Ключі `settings` відкат не чіпає.
